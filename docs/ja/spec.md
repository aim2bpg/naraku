# Narakuの正規表現の仕様

## このファイルのフォーマット

このファイルは機械的にパースしてテストを自動生成できるように構造化されています。
テストケースは次の「仕様」のセクションに記述されています。

各テストケースは次のようなMarkdownの引用ブロックになっています。

```markdown
> **テストケース**： `<name>`
>
> * <match_assert>
> * <match_assert>
> * ...
>
> <description>
```

各 `<...>` はそれぞれ次のような意味です。

- `<name>`: テストケースの名前。一意なIDです
- `<match_assert>`: 個々の正規表現マッチングのテスト。1つのテストケースに複数記述できます。詳細な形式は後述します
- `<description>`: テストケースの解説。省略可能です

`<match_assert>` は次のような形式になります。

```markdown
> * `/<pattern>/<flags> =~ "<string>"` (enc=<encoding>) at <pos> => <match_result> (onigmo=<onigmo_result>)
```

各 `<...>` は次のような意味です。

- `<pattern>`: テスト対象の正規表現のパターン。
  `/` で終端するので `/` 自身を含めたい場合は `\/` とエスケープする必要があります。
  ただし、文字クラス中はエスケープが必要ありません。
  空白記号などの文字を含めたい場合、`<NAME>` 形式が利用可能です。
  `<NAME>` には `<TAB>` (0x09), `<LF>` (0x0A), `<VT>` (0x0B), `<FF>` (0x0C), `<CR>` (0x0D)、そして `<xHH>` (`HH` は2桁の16進数の数値で、その値になる) が使えます。
  これらはプレースホルダーで、実際の文字列中はその値に置換されます。
  `<xHH>` を含む場合、その文字列は非ASCIIの文字を含んではいけません。
- `<flags>`: テスト対象の正規表現のフラグ。
  Rubyで有効なものが指定できます。つまり `i`, `m`, `x`, `a`, `u`, `s`, `e`, `n` が指定できます。
- `<string>`: マッチ対象の文字列。
  通常のRuby文字列で使えるエスケープシーケンスが利用できます。
  これはエンコーディングで正しいバイト列である必要があります。
- `<encoding>`: スクリプトエンコーディング。省略可能で、デフォルトは `UTF-8` です。
  `<pattern>` と `<string>` はこのエンコーディングでエンコードされます。
  パターンのエンコーディングを固定したい場合は、この値と `<flags>` で指定するエンコーディング (`s`, `e` のいずれか) を合わせる必要があります。
  テストに利用するエンコーディングは `UTF-8` (明記はしない), `UTF-16LE`, `Windows-31J`, `ASCII-8BIT`, `US-ASCII` のいずれかです。
- `<pos>`: マッチングの開始位置。省略可能で、デフォルトは `0` です。
  バイト数で指定します。
  またこの値は `<string>` の文字列の開始位置として有効なものでなければいけません。
- `<match_result>`: マッチ結果に期待する値。
  次のいずれかの値を取ります。
  * `` MATCH `[(<begin>, <end>), <capture>, ...]` ``:
    `<begin>` から `<end>` (どちらもバイト数) の範囲でマッチした場合。
    さらにキャプチャを含む場合 `<capture>` の情報を含む。
    `<capture>` は `(<begin>, <end>)` の形式 (キャプチャされてその範囲がバイト数で `<begin>` から `<end>`) か、`nil` (キャプチャされていない) になります。
  * `` NO MATCH ``:
    マッチしなかった場合。
  * `` ERROR `"<message>"` ``:
    エラーが起こった場合。
    エラーメッセージに `<message>` を含んでいることが期待されます。
- `<onigmo_result>`: 現在のOnigmo/Rubyのマッチング結果。省略可能です。
  値の形式は `<match_result>` と同様です。
  OnigmoとNarakuで期待する値が異なる場合のみ記述してください。

また、仕様中に「**Naraku拡張** (**ABC**):」から始まる文があることがあります。
この部分はOnigmoの挙動がバグである、もしくは直感的でないために、Narakuでは挙動を修正したことを表します。
**ABC** の部分は [`onigmo_bugs.md`](./onigmo_bugs.md) のIDです。

## 仕様

### 文字リテラル (Character Literals)

パターン中の特別な意味を持たない文字は文字リテラルとして、その文字自身にマッチします。
次の文字はパターン中で特別な意味を持つ文字として扱われます。

- `.`: ドット
- `*`, `+`, `?`, `{`: 繰り返し
- `[`: 文字クラス
- `(`, `)`: グループ
- `|`: 選択
- `^`, `$`: 行の先頭・末尾
- `\`: エスケープ文字
- `#`: コメント (`x` フラグが有効なとき)

> **テストケース**: `lit_simple`
> 
> * `/A/ =~ "A"` => MATCH `[(0, 1)]`
> * `/A/ =~ "B"` => NO MATCH

`]` や `}` にも特別な意味があるように思えますが、通常のリテラルのように扱えます。

> **テストケース**: `lit_close_bracket_and_brace`
>
> * `/]/ =~ "]"` => MATCH `[(0, 1)]`
> * `/]/ =~ "A"` => NO MATCH
> * `/}/ =~ "}"` => MATCH `[(0, 1)]`
> * `/}/ =~ "A"` => NO MATCH

また、`{` が回数指定の繰り返しになっていない場合も、通常のリテラルのように扱われます。

> **テストケース**: `lit_open_brace`
>
> * `/{/ =~ "{"` => MATCH `[(0, 1)]`
> * `/{/ =~ "A"` => NO MATCH
> * `/a{1/ =~ "a{1"` => MATCH `[(0, 3)]`
> * `/a{1/ =~ "aA1"` => NO MATCH

`x` フラグが有効でない場合、`#` も通常のリテラルのように扱われます。

> **テストケース**: `lit_hash`
>
> * `/#/ =~ "#"` => MATCH `[(0, 1)]`
> * `/#/ =~ "A"` => NO MATCH

パターンの文字列は与えられたエンコーディングでの正しいバイト列でなければなりません。

> **テストケース**: `lit_valid_bytes`
>
> * `/<x90>/ =~ "\x90"` (enc=ASCII-8BIT) => MATCH `[(0, 1)]`
> * `/<x90>/ =~ "A"` (enc=ASCII-8BIT) => NO MATCH
> * `/<x90>/ =~ "A"` (enc=US-ASCII) => ERROR `"invalid multibyte char"`

**議論**: ここのエラーメッセージはおかしい ("character" ではなく "char" となっている) 気がします。
エラーが出ているタイミングが通常とは異なるのではないかと思います。

### エスケープシーケンス (Escape Sequences)

特別な意味を持つ文字に `\` を付けることで、その文字にマッチします。
例えば `\.` や `\*` は `"."` や `"*"` にマッチします。

> **テストケース**: `esc_special`
>
> * `/\./ =~ "."` => MATCH `[(0, 1)]`
> * `/\./ =~ "A"` => NO MATCH
> * `/\*/ =~ "*"` => MATCH `[(0, 1)]`
> * `/\*/ =~ "A"` => NO MATCH
> * `/\+/ =~ "+"` => MATCH `[(0, 1)]`
> * `/\+/ =~ "A"` => NO MATCH
> * `/\?/ =~ "?"` => MATCH `[(0, 1)]`
> * `/\?/ =~ "A"` => NO MATCH
> * `/\{/ =~ "{"` => MATCH `[(0, 1)]`
> * `/\{/ =~ "A"` => NO MATCH
> * `/\}/ =~ "}"` => MATCH `[(0, 1)]`
> * `/\}/ =~ "A"` => NO MATCH
> * `/\[/ =~ "["` => MATCH `[(0, 1)]`
> * `/\[/ =~ "A"` => NO MATCH
> * `/\]/ =~ "]"` => MATCH `[(0, 1)]`
> * `/\]/ =~ "A"` => NO MATCH
> * `/\(/ =~ "("` => MATCH `[(0, 1)]`
> * `/\(/ =~ "A"` => NO MATCH
> * `/\)/ =~ ")"` => MATCH `[(0, 1)]`
> * `/\)/ =~ "A"` => NO MATCH
> * `/\|/ =~ "|"` => MATCH `[(0, 1)]`
> * `/\|/ =~ "A"` => NO MATCH
> * `/\^/ =~ "^"` => MATCH `[(0, 1)]`
> * `/\^/ =~ "A"` => NO MATCH
> * `/\$/ =~ "$"` => MATCH `[(0, 1)]`
> * `/\$/ =~ "A"` => NO MATCH
> * `/\\/ =~ "\\"` => MATCH `[(0, 1)]`
> * `/\\/ =~ "A"` => NO MATCH
> * `/\#/ =~ "#"` => MATCH `[(0, 1)]`
> * `/\#/ =~ "A"` => NO MATCH

特別な意味を持たない文字でも、エスケープシーケンスとしての意味を持たない文字であれば、その文字にマッチします。

> **テストケース**: `esc_not_special`
>
> * `/\"/ =~ "\""` => MATCH `[(0, 1)]`
> * `/\あ/ =~ "あ"` => MATCH `[(0, 3)]`

他にもRubyの文字列リテラルと同様のエスケープシーケンスが利用できます。

- `\a`: ベル文字 (0x07)
- `\t`: 水平タブ (0x09)
- `\n`: 改行 (0x0A)
- `\v`: 垂直タブ (0x0B)
- `\f`: フォームフィード (0x0C)
- `\r`: キャリッジリターン (0x0D)
- `\e`: エスケープ文字 (0x1B)

ただしRubyの文字列リテラルでは空白を表す `\s` の意味は異なります ([エスケープクラス](#エスケープクラス-shorthand-classes)を参照)。

> **テストケース**: `esc_simple`
>
> * `/\a/ =~ "\a"` => MATCH `[(0, 1)]`
> * `/\t/ =~ "\t"` => MATCH `[(0, 1)]`
> * `/\n/ =~ "\n"` => MATCH `[(0, 1)]`
> * `/\v/ =~ "\v"` => MATCH `[(0, 1)]`
> * `/\f/ =~ "\f"` => MATCH `[(0, 1)]`
> * `/\r/ =~ "\r"` => MATCH `[(0, 1)]`
> * `/\e/ =~ "\e"` => MATCH `[(0, 1)]`

`\x` や `\u`、`\C` や `\M` は続く文字列により、どのような文字を表すか決まります。

- `\xHH`: 2文字の16進数の数値が続き、そのバイト値の文字を表します。
- `\uHHHH`: 4文字の16進数の数値が続き、その数値のコードポイントの文字を表します。
- `\u{HH...}`: `{...}` で囲われた中にスペース区切りの16進数の数値が続き、それぞれのコードポイントの文字の列を表します。
- `\C-X`, `\cX`: コントロール文字を表します。`X` はバイト値の文字で `(X.ord % 0x20) | (X.ord & 0x80)` のバイト値になります。
- `\M-X`: メタ文字を表します。`X` はバイト値の文字で `X.ord | 0x80` のバイト値になります。

> **テストケース**: `esc_complex`
> 
> * `/\x41/ =~ "A"` => MATCH `[(0, 1)]`
> * `/\x41/ =~ "B"` => NO MATCH
> * `/\u0041/ =~ "A"` => MATCH `[(0, 1)]`
> * `/\u3042/ =~ "あ"` => MATCH `[(0, 3)]`
> * `/\u{0041}/ =~ "A"` => MATCH `[(0, 1)]`
> * `/\u{3042}/ =~ "あ"` => MATCH `[(0, 3)]`
> * `/\u{3042 3044}/ =~ "あい"` => MATCH `[(0, 6)]`
> * `/\C-A/ =~ "\x01"` => MATCH `[(0, 1)]`
> * `/\cA/ =~ "\x01"` => MATCH `[(0, 1)]`
> * `/\M-A/ =~ "\xC1"` (enc=ASCII-8BIT) => MATCH `[(0, 1)]`

`\u{HH...}` で16進数の数値の区切りとして使えるのは `\x20`, `\t`, `\v`, `\f`, `\r` のいずれかです (`\n` は含みません)。

> **テストケース**: `esc_brace_sep`
>
> * `/\u{3042 3044}/ =~ "あい"` => MATCH `[(0, 6)]`
> * `/\u{  3042  3044  }/ =~ "あい"` => MATCH `[(0, 6)]`
> * `/\u{3042 <TAB> 3044}/ =~ "あい"` => MATCH `[(0, 6)]`
> * `/\u{3042 <VT> 3044}/ =~ "あい"` => MATCH `[(0, 6)]`
> * `/\u{3042 <FF> 3044}/ =~ "あい"` => MATCH `[(0, 6)]`
> * `/\u{3042 <CR> 3044}/ =~ "あい"` => MATCH `[(0, 6)]`

**Naraku拡張** (**ES1**): Onigmoでは区切り文字に `\n` も含みますが、この挙動はRubyの文字列リテラルでの `\u{HH...}` と一貫性がないため、Rubyの文字列リテラルの挙動に統一します。

> **テストケース**: `esc_brace_sep_newline`
>
> * `/\u{3042 <LF> 3044}/ =~ "あい"` => ERROR `"invalid Unicode escape sequence"` (onigmo=MATCH `[(0, 6)]`)

`\uHHHH` および `\u{HH...}` を含む場合、そのパターンはUnicodeエンコーディングでなければなりません。
エンコーディングが固定されていない場合、`UTF-8` に固定されます ([エンコーディング](#エンコーディング-encoding)を参照)。

> **テストケース**: `esc_unicode`
>
> * `/\u3042/ =~ "あ"` (enc=Windows-31J) => ERROR `"incompatible encoding regexp match"`
> * `/\u{3042}/ =~ "あ"` (enc=Windows-31J) => ERROR `"incompatible encoding regexp match"`
> * `/\u3042/s =~ "あ"` (enc=Windows-31J) => ERROR `"incompatible character encoding"`
> * `/\u{3042}/s =~ "あ"` (enc=Windows-31J) => ERROR `"incompatible character encoding"`
>
> `/\u3042/` および `/\u{3042}/` はエンコーディングが固定されていないので、マッチング時にエンコーディングが異なるためエラーが出ます。
> 一方、`/\u3042/s` と `/\u{3042}/s` はエンコーディングが固定されているので、正規表現のパース時にエラーが出ます。

`\C-X` や `\cX`, `\M-X` の `X` の部分はバイト値を表す任意のリテラルが可能です。
エスケープシーケンスでも構いません。

> **テストケース**: `esc_control_meta`
>
> * `/\C-\\/ =~ "\x1C"` => MATCH `[(0, 1)]`
> * `/\C-\xE1/ =~ "\x81"` (enc=ASCII-8BIT) => MATCH `[(0, 1)]`
> * `/\c\\/ =~ "\x1C"` => MATCH `[(0, 1)]`
> * `/\M-\xE1/ =~ "\xE1"` (enc=ASCII-8BIT) => MATCH `[(0, 1)]`

`\xHH` や `\M-A` の表すバイト値が複数バイト文字の先頭の場合、続くバイト列が (エスケープシーケンスを解除した上で) 正しいバイト列となっていなければなりません。
また `\uHHHH` や `\u{HH...}` の表すコードポイントも、そのエンコーディングで正しいものである必要があります。

> **テストケース**: `esc_valid_bytes`
>
> * `/\xE3\x81\x82/ =~ "あ"` => MATCH `[(0, 3)]`
> * `/\xE3\C-\x81\M-\C-B/ =~ "あ"` => MATCH `[(0, 3)]`
> * `/\x95\x5C/ =~ "表"` (enc=Windows-31J) => MATCH `[(0, 2)]`
> * `/\x95\x41/ =~ "柊"` (enc=Windows-31J) => MATCH `[(0, 2)]`
> * `/\xED/ =~ "😊"` => ERROR `"too short escaped multibyte character"`
> * `/\xED\xA0\xBD/ =~ "😊"` => ERROR `"invalid multibyte escape"`
> * `/\uD83D/ =~ "😊"` => ERROR `"invalid Unicode escape sequence"`
> * `/\u{D83D}/ =~ "😊"` => ERROR `"invalid Unicode escape sequence"`
> * `/\x20/ =~ " "` (enc=UTF-16LE) => ERROR `"too short multibyte code string"`
>
> `\xED\xA0\xBD` や `\uD83D` はサロゲートペアの片方です。

**議論**: enc=UTF-16LEのケースではエラーメッセージが不正なバイト列を含んでいます (参照: **ES1**)。

**Naraku拡張** (**ES1**): Rubyの文字列リテラルと同様に、続くバイト列はリテラルでも許容されます。

> **テストケース**: `esc_valid_bytes_extended`
>
> * `/\x95\\/ =~ "表"` (enc=Windows-31J) => MATCH `[(0, 2)]`
> * `/\x95A/ =~ "柊"` (enc=Windows-31J) => MATCH `[(0, 2)]` (onigmo=ERROR `"too short escaped multibyte character"`)

### ドット (Dot)

`.` は改行文字 (`"\n"`) を除く任意の文字にマッチします。
`m` フラグが有効な場合、改行文字にもマッチします。

> **テストケース**: `dot_simple`
>
> * `/./ =~ "A"` => MATCH `[(0, 1)]`
> * `/./ =~ "\n"` => NO MATCH
> * `/(?m)./ =~ "A"` => MATCH `[(0, 1)]`
> * `/(?m)./ =~ "\n"` => MATCH `[(0, 1)]`

複数バイト文字にも正しく1文字だけマッチします。

> **テストケース**: `dot_multibyte`
>
> * `/./ =~ "あ"` => MATCH `[(0, 3)]`
> * `/./ =~ "あ"` (enc=Windows-31J) => MATCH `[(0, 2)]`

### 改行 (Newlines)

`\R` は改行にマッチします。
具体的には `\n` (0x0A) から `\r` (0x0D) までの文字のいずれかにマッチします。
`\r\n` が並んでいる場合は、これらにまとめてマッチします。

> **テストケース**: `newline_simple`
>
> * `/\R/ =~ "A"` => NO MATCH
> * `/\R/ =~ "\n"` => MATCH `[(0, 1)]`
> * `/\R/ =~ "\v"` => MATCH `[(0, 1)]`
> * `/\R/ =~ "\f"` => MATCH `[(0, 1)]`
> * `/\R/ =~ "\r"` => MATCH `[(0, 1)]`
> * `/\R/ =~ "\r\n"` => MATCH `[(0, 2)]`

さらに、Unicodeエンコーディングの場合追加で U+0085, U+2028, U+2029 の3文字にもマッチします。
これらは `a` フラグや `u` フラグの影響を受けません。

> **テストケース**: `newline_charset_specific`
>
> * `/\R/ =~ "\u{0085}"` => MATCH `[(0, 2)]`
> * `/\R/ =~ "\u{2028}"` => MATCH `[(0, 3)]`
> * `/\R/ =~ "\u{2029}"` => MATCH `[(0, 3)]`
> * `/(?a)\R/ =~ "\u{2028}"` => MATCH `[(0, 3)]`
> * `/(?u)\R/ =~ "\u{2028}"` => MATCH `[(0, 3)]`

### 書記素クラスタ (Grapheme Clusters)

`\X` は現在の位置を書記素クラスタの開始位置と見做したときの書記素クラスタの終了位置までマッチします。
文字列の先頭から考えたときの、厳密な書記素クラスタ全体にマッチするようにするためには、後読みが必要になるためこのような仕様になっています。

具体的には [UAX #29](https://www.unicode.org/reports/tr29/) の "extended grapheme cluster" の正規表現を実装しています。

> **テストケース**: `gc_simple`
>
> * `/\X/ =~ "a"` => MATCH `[(0, 1)]`
> * `/\X/ =~ "あ"` => MATCH `[(0, 3)]`
> * `/\X/ =~ "か\u{309A}"` => MATCH `[(0, 6)]`
> * `/\X/ =~ "\u{0067}\u{0308}"` => MATCH `[(0, 3)]`
> * `/\X/ =~ "\u{AC01}"` => MATCH `[(0, 3)]`
> * `/\X/ =~ "\u{1100}\u{1161}\u{11A8}"` => MATCH `[(0, 9)]`
> * `/\X/ =~ "\u{0BA8}\u{0BBF}"` => MATCH `[(0, 6)]`
> * `/\X/ =~ "\u{1F1EE}\u{1F1F8}"` => MATCH `[(0, 8)]`
> * `/\X/ =~ "\u{1F1EE}\u{1F1F8}\u{1F1F8}"` at 4 => MATCH `[(4, 12)]`
>
> 最後の例は、本来の書記素クラスタの境界は8バイト目ですが、それを実現するには後読みが必要なため、4バイト目を書記素クラスタの開始位置と見做したときの書記素クラスタの終了位置である12バイト目までマッチしています。

**議論**: 理想としてはマッチの始まりが書記素クラスタの開始位置でなければ `\X` はマッチすべきではないと考えられます。
しかし、それの実現には先述のように後読みが必要になるし、後方互換性の問題もあります (参照: **LB1**)。

非Unicodeエンコーディングでは `/\r\n|(?m:.)/` と同等のものとして扱われます。

> **テストケース**: `gc_non_unicode`
>
> * `/\X/ =~ "a"` (enc=Windows-31J) => MATCH `[(0, 1)]`
> * `/\X/ =~ "あ"` (enc=Windows-31J) => MATCH `[(0, 2)]`
> * `/\X/ =~ "\r\n"` (enc=Windows-31J) => MATCH `[(0, 2)]`

このエスケープシーケンスは `a` フラグの影響を受けません。

> **テストケース**: `gc_ascii_flag`
>
> * `/(?a)\X/ =~ "あ"` => MATCH `[(0, 3)]`
> * `/(?a)\X/ =~ "か\u{309A}"` => MATCH `[(0, 6)]`

**Naraku拡張** (**LB1**): 後読み中では `\X` はエラーになります。
現在の実装や意味論では直感的に反する挙動を示す場合が多いからです。
仮に今の実装で後読み中の `\X` を許可したとすると、`/(?<=\X)/ =~ "か\u{309A}"` は3バイト目でマッチすることになりますが、これは明らかに直感に反します。

> **テストケース**: `gc_lookbehind`
>
> * `/(?<=\X)/ =~ "a"` => ERROR `"invalid pattern in look-behind"`

**議論**: もっとspecificなエラーメッセージにしてもいいかもしれません。

### 文字タイプ (Character Types)

エスケープシーケンスの中には特定の種類の文字にマッチするものもあります。
`\w`, `\s`, `\d`, `\h` の4つが相当します。
また、これらは大文字にする (`\W`, `\S`, `\D`, `\H`) と意味が反転します。

- `\w`: 単語を構成する文字 (`[a-zA-Z0-9_]`) にマッチします。
- `\W`: 単語を構成する文字以外 (`[^a-zA-Z0-9]`) にマッチします。
- `\s`: 空白文字 (`[ \t\r\n\f\v]`) にマッチします。
- `\S`: 空白文字以外 (`[^ \t\r\n\f\v]`) にマッチします。
- `\d`: 10進数字 (`[0-9]`) にマッチします。
- `\D`: 10進数字以外 (`[^0-9]`) にマッチします。
- `\h`: 16進数字 (`[0-9a-fA-F]`) にマッチします。
- `\H`: 16進数字以外 (`[^0-9a-fA-F]`) にマッチします。

> **テストケース**: `shorthand_simple`
>
> * `/\w/ =~ "a"` => MATCH `[(0, 1)]`
> * `/\w/ =~ "A"` => MATCH `[(0, 1)]`
> * `/\w/ =~ "X"` => MATCH `[(0, 1)]`
> * `/\w/ =~ "0"` => MATCH `[(0, 1)]`
> * `/\w/ =~ "5"` => MATCH `[(0, 1)]`
> * `/\w/ =~ "_"` => MATCH `[(0, 1)]`
> * `/\w/ =~ "."` => NO MATCH
> * `/\W/ =~ "."` => MATCH `[(0, 1)]`
> * `/\W/ =~ " "` => MATCH `[(0, 1)]`
> * `/\W/ =~ "a"` => NO MATCH
> * `/\W/ =~ "_"` => NO MATCH
> * `/\s/ =~ " "` => MATCH `[(0, 1)]`
> * `/\s/ =~ "\t"` => MATCH `[(0, 1)]`
> * `/\s/ =~ "\r"` => MATCH `[(0, 1)]`
> * `/\s/ =~ "\n"` => MATCH `[(0, 1)]`
> * `/\s/ =~ "\f"` => MATCH `[(0, 1)]`
> * `/\s/ =~ "\v"` => MATCH `[(0, 1)]`

### Unicodeプロパティ (Unicode Properties)

`\p{...}` は特定のUnicodeプロパティを持つ文字にマッチします。
一方、`\P{...}` は特定のUnicodeプロパティを持たない文字にマッチします。

サポートされているUnicodeプロパティは以下の通りです。

- `General_Category`
- `Script`
- `Age`
- `Block`
- `Grapheme_Cluster_Break`
- `PropList.txt` と `DerivedCoreProperties.txt` に記載されているプロパティ
  (`Indic_Conjunct_Break` を含む)
- `emoji/emoji-data.txt` に記載されているプロパティ

`General_Category` と `Script` は値だけを指定しても認識されます。
また、`Block` は `In` を前置しても認識されます。

Unicodeプロパティ以外に、次の16種類のプロパティ名もサポートされます。
これらの多くはPOSIX文字クラスに対応しています。

- `Alnum`
- `Alpha`
- `Blank`
- `Cntrl`
- `Digit`
- `Graph`
- `Lower`
- `Print`
- `Punct`
- `Space`
- `Upper`
- `XDigit`
- `ASCII`
- `Any`
- `Assigned`
- `XPosixPunct`

プロパティ名と値は空白文字やアンダースコア、ハイフンを無視して認識されます。

**Naraku拡張** (**UP1**): 次のプロパティも追加でサポートします。

- `Script_Extensions`
- `Canonical_Combining_Class`

また、全てのプロパティで一貫して `プロパティ名=値` の形式もサポートするようにします。
さらに、プロパティ名や値の両方で省略系などのエイリアスもサポートします。

**Naraku拡張** (**UP2**): Unicode以外のエンコーディングの場合でも、追加の16種類のプロパティ名と `Script` プロパティの値についてはサポートします。
